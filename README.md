# PDDL action-schema order and LLM planning

Code and analysis data for a study of how the order of action schemas in a PDDL domain affects plans generated by large language models. The experiment compares 10 ordering rules on 20 logistics problems using DeepSeek V4 Flash, GPT-OSS-120B, and Nemotron-3-Super, with 15 runs per model, problem, and order (9,000 outcomes).

The ordering rules change the presentation of complete action schemas without changing the planning domain semantics. Six rules use a reference plan and are therefore constructed separately for each problem.

## What is included

| Path | Contents |
| --- | --- |
| `materials/logistics/` | Source PDDL domain, 20 problems and reference plans, and the domain variants used in the experiment. |
| `materials/logistics/alpha/` | Per-run validation metrics. There are 8,998 reduced `llm_result.json` files and two preserved `llm.plan` files from which the remaining outcomes can be recovered. |
| `materials/stats/order_audit/` | Saved outcome counts, metric summaries, Kendall distances, and task-level statistical results reported in the article. |
| `materials/stats/*.py` | Scripts for aggregating results, statistical analysis, and plotting. |
| Root-level `*.py` | Experiment configuration, PDDL variant generation, model calls, and plan checking. |
| `FILE_INVENTORY.tsv` | File-by-file inventory of the archive. |
| `SHA256SUMS` | Checksums from the original archive; see the note below. |

The per-run JSON files contain only the validation fields needed by the analysis. Raw model responses, reasoning traces, token counts, and billing records are not included. The saved data are sufficient to reproduce the article's statistical tables and figures without an API key or a VAL installation. They are not sufficient to replay the original model calls or revalidate every original answer from its raw text.

## Reproduce the analysis

Run these commands from the repository root with Python 3.10 or newer:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

python materials/stats/run_task_mean_tests.py
python materials/stats/run_secondary_task_bootstrap.py
python materials/stats/plot_current_all_metrics.py --output-dir figures
python materials/stats/plot_article_order_audit.py
```

The first two scripts reproduce the task-level centered-bootstrap results in `materials/stats/order_audit/`. `run_task_mean_tests.py` also writes an additional sensitivity result that is not used for the article's conclusions. The plotting scripts produce:

- Article Figure 1: `figures/figure_2_math_no_wild.pdf` (eight plan-quality metrics).
- Article Figure 2: `materials/stats/order_audit/manuscript_figures/figure_3_four_outcomes_all_ten.png` (four validation outcomes).

The figure filenames retain their names from earlier analysis drafts; the article numbers its figures 1 and 2. `plot_article_order_audit.py` also creates a supplementary goal-attainment plot. The random seeds and resampling counts are set in the scripts and can be changed through their command-line options.

The saved `outcome_counts.csv` and `metric_summaries.csv` are inputs to the commands above. To rebuild these summaries from the reduced per-run data first, run:

```bash
python materials/stats/run_order_audit.py
```

That script also writes older exploratory analyses. The article's principal tests are the `task_mean_*.csv` files produced by the first two commands.

## Scope of the archive

The root-level runner can make paid OpenRouter calls and the validator code can invoke VAL when supplied with new plans. Neither is needed for the reproduction commands above. Avoid running `main.py prepare --force` in this archive: it replaces saved variant directories and does not recreate all task-specific variants by itself.

`SHA256SUMS` was generated before this README was updated for the standalone repository, so its `README.md` entry is outdated. The other archived files can be checked with:

```bash
grep -v '  README.md$' SHA256SUMS | sha256sum --check -
```
